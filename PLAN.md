## Known problems

- The JSON type aliases promise more than a JSON column keeps: `JSONIterable` allows a tuple, which comes back as a list, and `dict[Hashable, ...]` allows non-string keys, which come back as strings (`{1: "a"}` returns as `{"1": "a"}`). Checked 2026-10-21. Fixing it means narrowing the aliases to lists and string keys (a typing change) or validating on save; not changed without the user's approval. Option found later: convert in the `genotype` and `tags` setters, so `ind.genotype = (1, 2)` reads back `[1, 2]` at once and the value never changes on its way through the database, with the aliases narrowed too. A storage format that keeps tuples was rejected: the column would stop being plain JSON and `Archive`'s queries get harder. Asked 2026-10-21; the user has not chosen yet. The question led to goal 8 instead ("genotype is a bit special"): numpy genotypes now round-trip exactly, but a tuple or a non-string key in a JSON genotype or in tags still comes back changed; `JsonCodec`'s docstring and `tests/test_codecs.py::test_json_codec_turns_tuples_and_number_keys_into_json` say so.
